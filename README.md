# transformer-llm

A from-scratch, character-level language model built with PyTorch, progressing from a simple bigram model to a full decoder-only Transformer (GPT-style).

## Repository Structure

```
.
├── bigram.py       # Baseline: a single-embedding-table bigram model
├── main.py         # Full Transformer: self-attention, multi-head attention, blocks
├── gpt_dev.ipynb   # Development notebook walking through the build step by step
├── input.txt       # Training corpus (Tiny Shakespeare)
├── output.txt      # Sample text generated by the trained model
├── LICENSE
└── .gitignore
```

## Two Models, One Progression

**`bigram.py`** — the simplest possible baseline. A single embedding table maps each character directly to logits for the next character, with no attention and no context beyond the current token.

**`main.py`** — the full model. Adds:
- Token + positional embeddings
- Multi-head self-attention (`Head`, `MultiHeadAttention`) with causal masking
- Transformer blocks (`Block`) combining attention and a feed-forward MLP, with residual connections, pre-LayerNorm, and dropout
- A language-modeling head that projects back to vocabulary logits

**`gpt_dev.ipynb`** walks through the reasoning behind each of these additions interactively, useful if you want to see the model built up piece by piece rather than just reading the final script.

## Requirements

- Python 3.8+
- [PyTorch](https://pytorch.org/) (CUDA optional — both scripts fall back to CPU automatically)

```bash
pip install torch
```

## Dataset

`input.txt` (Tiny Shakespeare) is already included in this repo. If you want to re-download it or swap in your own corpus:

```bash
wget https://raw.githubusercontent.com/karpathy/char-rnn/master/data/tinyshakespeare/input.txt
```

## Usage

Run the bigram baseline:
```bash
python bigram.py
```

Run the full Transformer:
```bash
python main.py
```

Each script will:
1. Tokenize `input.txt` at the character level
2. Split the data into 90% train / 10% validation
3. Train for `max_iters` steps, printing train/val loss every `eval_interval` steps
4. Generate 500 characters of new text from the trained model and print them to the console

Sample output from a trained run is saved in `output.txt`.

## Hyperparameters

| Parameter       | `bigram.py` | `main.py` | Description                          |
|-----------------|-------------|-----------|---------------------------------------|
| `batch_size`    | 32          | 32        | Sequences processed in parallel       |
| `block_size`    | 8           | 8         | Max context length for predictions    |
| `max_iters`     | 3000        | 5000      | Total training iterations             |
| `eval_interval` | 300         | 500       | Steps between loss evaluations        |
| `learning_rate` | 1e-2        | 1e-3      | AdamW learning rate                   |
| `eval_iters`    | 200         | 200       | Batches averaged per loss estimate    |
| `n_embd`        | —           | 32        | Embedding dimension                   |
| `n_head`        | —           | 6         | Attention heads per block             |
| `n_layer`       | —           | 6         | Number of Transformer blocks          |
| `dropout`       | —           | 0.2       | Dropout rate                          |

Tune these at the top of either script — larger `n_embd`, `n_layer`, and `block_size` in `main.py` generally produce more coherent (but slower to train) generations.
